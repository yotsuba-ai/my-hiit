# MY HIIT

**アプリを使う：[MY HIITを開く](https://yotsuba-ai.github.io/my-hiit/)**

スマートフォンでURLを開き、「オフライン利用の準備ができました」を確認してください。iPhoneはSafariの共有メニューから「ホーム画面に追加」、AndroidはChromeのメニューから「アプリをインストール」または「ホーム画面に追加」で起動アイコンを作れます。

React + TypeScript + Vite で作成した、端末内保存のHIITタイマーです。

MVP：運動・休憩・周回・ウォームアップ・クールダウンの設定、種目の追加・削除・並び替え、実行画面、音声と効果音、一時停止・再開・リセット・スキップ、メニュー保存とワンタップ開始、PWAを実装しています。初期プリセットは14分です。プリセットの編集は別のカスタムメニューとして保存します。

## 起動

```sh
npm install
npm run dev
```

起動後はターミナルに表示される `/my-hiit/` のURLを開いてください。GitHub Pagesのリポジトリ名 `my-hiit` に合わせてViteのベースパスを設定しています。

## GitHub Pagesへの公開

`.github/workflows/deploy.yml` は `main` へのpush時に依存パッケージをインストールし、本番ビルドとテストが成功したときだけ `dist/` をGitHub Pagesへ公開します。Actions画面から手動実行も可能です。リポジトリの Settings → Pages → Source は **GitHub Actions** に設定します。

リポジトリ名を変更するときは `vite.config.ts` の `base` も新しい名前に変更してください。公開URLはデプロイの完了後にGitHubのSettings → Pagesで確認できます。

本番用ファイルとオフラインキャッシュ用サービスワーカーを生成する場合:

```sh
npm run build
npm run preview
```

開発環境はNode.js 22.23.4で確認済みです。本番ビルドは `dist/` に生成されます。開発サーバーではサービスワーカーを登録しません。

ホーム画面への追加とサービスワーカーには HTTPS（または localhost）が必要です。メニューはブラウザの `localStorage` に保存されます。ブラウザのデータを消すと保存したメニューも消えます。

## タイマーの仕様

- プリセットは、各種目の後に休憩を入れます。最後の種目の後にも休憩があります。合計14分です。
- 実行中は `Date.now()` と開始時刻との差で進捗を算出します。画面更新が遅れても、復帰時に正しい経過時間へ追いつきます。
- 画面ロック中やバックグラウンドでの音声・効果音はOSやブラウザに制限されるため、通知を保証できません。画面を開いたまま利用してください。
- 端末の時計を実行中に変更するとタイマーがずれる可能性があります。
- スキップも操作時の実時刻を参照します。一時停止中のスキップは停止状態を維持し、最終区間のスキップは直ちに完了します。
- 対応ブラウザでは実行中にScreen Wake Lockを要求し、画面消灯を防ぎます。画面復帰時に再取得し、一時停止・終了時に解放します。拒否された場合も画面内に無効と表示します。
- ページの再読み込みやOSによるプロセス終了後のセッション復元はMVP対象外です。保存したメニューは維持されます。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/workout.ts` | メニューモデル、プリセット、区間生成、入力検証 |
| `src/timer.ts` | 実時刻による経過時間計算・スキップ（UIに依存しない） |
| `src/storage.ts` | 端末内保存。保存形式のバージョンはキーの `v1` で管理 |
| `src/alerts.ts` | Web Audio効果音と日本語音声案内 |
| `src/useWakeLock.ts` | 画面消灯防止の取得・解放 |
| `src/PwaPanel.tsx` | オフライン準備状態、インストール案内 |
| `src/App.tsx` | 一覧・編集・セッション画面 |
| `scripts/generate-sw.mjs` | ビルド内容に基づくキャッシュ更新・オフライン配信 |

将来の自動提案は `Workout` を返す処理として追加できます。履歴や心拍連携はタイマー・通知・保存処理から分けて拡張してください。

この環境ではWork設定によりブラウザ操作が無効でした。画面の実表示、実際の音声出力、Wake Lock、インストール、実ブラウザでのオフライン動作は未検証です。iPhone・Androidの実機合格を意味しません。

## OS・ブラウザの制約

バックグラウンドではブラウザがタイマー更新を抑制するため、画面復帰時に時刻差から現在区間へ追いつきます。復帰までの各区間の音声を遡って連続再生する仕様ではありません。ロック中の通知は保証せず、画面にもその旨を表示します。

- [MDN：Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)
- [MDN：Screen Wake Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)
- [Apple：Web Push通知](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)

Web Pushはローカルの定刻通知とは別の仕組みです。MVPではサーバーやPush通知を使用しません。
